# 发布流程（构建 · 签名 · 公证 · 装订 · 校验 · 公布）

本文档描述如何从源码产出一个**可分发、已公证**的 `Mac小助手.app`，以及在没有证书时如何产出**明确标记为开发构建**的 ad-hoc 产物。整个链路由 `build_app.sh` 驱动，`dist/` 已被 gitignore。

> 边界：本项目只对你自有或已获授权的目标操作。发布链路不伪造 Apple 签名或 entitlement，未真正完成公证前绝不把产物标记成已公证。详见 [`SECURITY.md`](../SECURITY.md) 与 [`TODO.md`](../TODO.md) 的「Explicit Non-Goals」。

---

## 0. 前置条件

- macOS + Xcode 命令行工具（提供 `swift`、`codesign`、`xcrun notarytool`、`xcrun stapler`、`spctl`、`ditto`、`shasum`）。
- 发行构建还需要：
  - 一张 **Developer ID Application** 证书（在钥匙串里，来自你自己的 Apple Developer 账号）。
  - 一份可用于公证的 Apple 凭据（见下）。
- **所有证书、密码、API Key 一律通过环境变量传入，绝不写进仓库、脚本或本文件。** 本文档中出现的都是变量名和占位符，不是真实值。

---

## 1. 两种构建种类

`build_app.sh` 依据是否提供 `MA_SIGN_IDENTITY` 环境变量自动分流，并把结果如实写进 `Info.plist` 的 `MacAssistantBuildKind`（About 页会读取并显示）：

| 场景 | 触发条件 | 签名方式 | `MacAssistantBuildKind` |
| --- | --- | --- | --- |
| 开发构建 | 未设置 `MA_SIGN_IDENTITY` | `codesign --sign -`（ad-hoc） | `Development (ad-hoc, not notarized)` |
| 发行构建 | 设置了 `MA_SIGN_IDENTITY` | Developer ID + Hardened Runtime + 公证 + 装订 | `Release (Developer ID, notarized & stapled)` |

发行模式下任何一步失败都会**报错退出**，并删除可能被误标为已公证的半成品，绝不静默降级成 ad-hoc 却仍标为发行版。

## 2. 开发构建（无证书，快速迭代）

```bash
./build_app.sh release universal   # 默认 x86_64 + arm64 通用二进制
# 或本地快速迭代：
./build_app.sh release native      # 只编当前架构
```

产物：`dist/Mac小助手.app`（ad-hoc 签名，未公证）。macOS 首次打开可能拦截。用户看得到的说明写在 [README](../README.md#first-launch-blocked-by-macos) / [中文 README](README.zh-CN.md#首次打开被拦截)，不要只写在 About 页——进不去 App 就看不见。

## 3. 发行构建（Developer ID + 公证）

### 3.1 配置签名身份

```bash
# 从钥匙串里查出 Developer ID Application 身份的完整名称：
security find-identity -v -p codesigning
# 形如：Developer ID Application: Your Name (TEAMID)
export MA_SIGN_IDENTITY="Developer ID Application: Your Name (TEAMID)"
```

### 3.2 配置公证凭据（三选一）

**方式 A：钥匙串 profile（推荐，凭据只存在本机钥匙串）**

```bash
# 一次性存好（交互式，密码不落盘到仓库）：
xcrun notarytool store-credentials "MA_NOTARY" \
  --apple-id "you@example.com" --team-id "TEAMID"
# 之后：
export MA_NOTARY_KEYCHAIN_PROFILE="MA_NOTARY"
```

**方式 B：App Store Connect API Key**

```bash
export MA_NOTARY_API_KEY="/absolute/path/AuthKey_XXXX.p8"
export MA_NOTARY_API_KEY_ID="XXXXXXХХ"
export MA_NOTARY_API_ISSUER="xxxxxxxx-xxxx-xxxx-xxxx-xxxxxxxxxxxx"
```

**方式 C：Apple ID + App 专用密码**

```bash
export MA_NOTARY_APPLE_ID="you@example.com"
export MA_NOTARY_PASSWORD="app-specific-password"   # App 专用密码，非账号密码
export MA_TEAM_ID="TEAMID"
```

> 缺少任一凭据组合，脚本会直接报错退出，不会继续。

### 3.3 一键执行

```bash
./build_app.sh release universal
```

脚本会依次完成：

1. **构建** 通用二进制并组装 `.app`。
2. **签名**：由内向外先签可执行文件、再签整包，`--options runtime`（Hardened Runtime）+ `--entitlements Resources/MacAssistant.entitlements` + `--timestamp`（安全时间戳）。
3. **本地校验**：`codesign --verify --strict`。
4. **公证**：`ditto` 打成 zip → `xcrun notarytool submit --wait`，并显式校验状态必须为 `Accepted`。
5. **装订**：`xcrun stapler staple` + `xcrun stapler validate`。
6. **Gatekeeper 评估**：`spctl --assess --type execute`（只有真正公证并装订后才 accepted）。
7. **公布校验值**：输出可执行文件与分发 zip 的 SHA-256，并写入 `dist/Mac小助手-<版本>.zip.sha256`。

---

## 4. 校验与公布

- 分发时同时公布 `dist/Mac小助手-<版本>.zip` 的 SHA-256（脚本已生成 `.sha256` 旁文件）。
- 用户可自行核对：

```bash
shasum -a 256 Mac小助手-<版本>.zip
# 或
shasum -a 256 -c Mac小助手-<版本>.zip.sha256
```

- 用户也可本地确认公证已装订：

```bash
xcrun stapler validate Mac小助手.app
spctl --assess --type execute --verbose=4 Mac小助手.app
```

---

## 5. entitlement 说明

签名使用的 `Resources/MacAssistant.entitlements` 是一套**最小集合**（实际接近空），因为本 App 刻意不启用 App Sandbox，也不把外部代码载入自身进程；调用 `codesign`/`ldid`/`dpkg-deb` 等都是子进程，Hardened Runtime 不需要为此额外开权限。该文件里逐条记录了「哪些能力被评估过、为什么不开」，改动请集中在那一处。
